# 氚云流程审批状态批量修复方法

> 适用场景：把氚云流程表单中卡在"进行中"的审批批量改成"已完成"。
> 本文方法已在生产环境实测：一次性结束 15932 个卡住实例，0 失败，复查归零（2026-10-14）。

## 1. 问题背景与关键结论

**需求**：检验记录表单（`D287764b96d54298e814d06b87e5f99a28658ad`，3.6万条数据）里大量记录的审批状态卡在"进行中"，需要批量改成"已完成"。

**核心结论（实测验证）**：

| 结论 | 说明 |
|---|---|
| 界面"审批状态"读的是**流程实例状态**，不是业务数据的 `Status` 字段 | 证据：三条记录的数据 Status 全=2，界面却分别显示"进行中"和"已完成"——区别在流程实例是否走完 |
| `UpdateBizObject` 改 `Status` 字段**对界面审批状态无效** | API 返回成功、字段确实被改，但界面照样显示"进行中"。此路不通 |
| 氚云标准 OpenAPI（8个公共方法）全是数据层操作，**碰不到流程实例** | 流程类 ActionName 一律返回"未指定类名称" |
| 正确方案：**自定义接口（后端代码）+ FinishInstanceMessage 结束流程实例** | 见下文 |

**流程实例状态枚举**（H_WorkflowInstance.state）：`1`=正在启动、`2`=进行中、`3`=正在结束、`4`=已完成、`5`=已取消。

## 2. 原理

氚云表单设计器的"后端代码"支持写继承 `H3.SmartForm.RestApiController` 的自定义接口类，第三方通过同一个 OpenAPI 入口（`https://www.h3yun.com/OpenApi/Invoke`）传入 `Controller` 类名即可调用。后端代码持有引擎级权限，可以调流程引擎直接结束流程实例：

```csharp
// 结束流程（官方写法）：实例状态变为"已完成"，界面审批状态随之更新
H3.Workflow.Instance.WorkflowInstance instance =
    engine.WorkflowInstanceManager.GetWorkflowInstance(instanceId);
H3.Workflow.Messages.FinishInstanceMessage msg =
    new H3.Workflow.Messages.FinishInstanceMessage(instanceId, (int)instance.FinalTokenId);
engine.WorkflowInstanceManager.SendMessage(msg);

// 取消流程（备用，状态变"已取消"）
// new H3.Workflow.Messages.CancelInstanceMessage(instanceId, false) + SendMessage
```

要点：
- 自定义接口运行时**无登录人上下文**，涉及用户操作时用 `H3.Organization.User.SystemUserId` 代替 `this.Request.UserContext.UserId`
- `FinishInstanceMessage` 只对进行中（state 1/2）的实例有意义，代码里应先查状态再操作，天然幂等（重复调用返回 skip）
- 接口本身无权限校验，安全屏障是 `EngineSecret`（妥善保管，勿外泄）

## 3. 实施步骤

### 3.1 部署自定义接口

1. 电脑端氚云 → 进入目标表单所在应用 → **表单设计**（建议放专用空表单，也可直接放目标表单）
2. 打开设计器的**"后端代码"**编辑器
3. 在**默认生成的 `SmartFormController` 类后面**追加下面的控制器类（默认类不可删除），保存并**发布**表单

```csharp
// ===== 自定义接口 v3：查状态 / 单条结束 / 批量结束 =====
public class WfFixController : H3.SmartForm.RestApiController
{
    public WfFixController(H3.SmartForm.RestApiRequest request) : base(request) { }

    protected override void OnInvoke(string actionName, H3.SmartForm.RestApiResponse response)
    {
        try
        {
            if (actionName == "QueryInstanceStates")
            {
                // 只查状态，不改数据。InstanceIds: 逗号分隔
                string ids = this.Request.GetValue<string>("InstanceIds", string.Empty);
                H3.IEngine engine = this.Request.Engine;

                Dictionary<string, int> tally = new Dictionary<string, int>();
                List<string> running = new List<string>();
                foreach (string raw in ids.Split(new char[] { ',' }, StringSplitOptions.RemoveEmptyEntries))
                {
                    string iid = raw.Trim();
                    H3.Workflow.Instance.WorkflowInstance inst =
                        engine.WorkflowInstanceManager.GetWorkflowInstance(iid);
                    int st = inst == null ? -1 : (int)inst.State;
                    if (tally.ContainsKey(st.ToString())) tally[st.ToString()]++;
                    else tally[st.ToString()] = 1;
                    if (st == 1 || st == 2) running.Add(iid);
                }

                List<string> parts = new List<string>();
                foreach (KeyValuePair<string, int> kv in tally) parts.Add(kv.Key + ":" + kv.Value);
                response.ReturnData.Add("result", "success");
                response.ReturnData.Add("stateTally", string.Join(",", parts));
                response.ReturnData.Add("runningIds", string.Join(",", running));
            }
            else if (actionName == "FinishInstance")
            {
                string instanceId = this.Request.GetValue<string>("InstanceId", string.Empty);
                H3.IEngine engine = this.Request.Engine;

                H3.Workflow.Instance.WorkflowInstance instance =
                    engine.WorkflowInstanceManager.GetWorkflowInstance(instanceId);
                if (instance == null)
                {
                    response.ReturnData.Add("result", "error");
                    response.ReturnData.Add("message", "流程实例不存在: " + instanceId);
                    return;
                }

                int state = (int)instance.State;
                if (state != 1 && state != 2)
                {
                    response.ReturnData.Add("result", "skip");
                    response.ReturnData.Add("message", "流程非进行中，当前state=" + state);
                    return;
                }

                H3.Workflow.Messages.FinishInstanceMessage msg =
                    new H3.Workflow.Messages.FinishInstanceMessage(instanceId, (int)instance.FinalTokenId);
                engine.WorkflowInstanceManager.SendMessage(msg);

                response.ReturnData.Add("result", "success");
                response.ReturnData.Add("message", "已结束，原state=" + state);
            }
            else if (actionName == "FinishInstanceBatch")
            {
                // InstanceIds: 逗号分隔，只结束进行中(state 1/2)的
                string ids = this.Request.GetValue<string>("InstanceIds", string.Empty);
                H3.IEngine engine = this.Request.Engine;

                int ok = 0, skip = 0, miss = 0, err = 0;
                List<string> errors = new List<string>();

                foreach (string raw in ids.Split(new char[] { ',' }, StringSplitOptions.RemoveEmptyEntries))
                {
                    string iid = raw.Trim();
                    try
                    {
                        H3.Workflow.Instance.WorkflowInstance inst =
                            engine.WorkflowInstanceManager.GetWorkflowInstance(iid);
                        if (inst == null) { miss++; continue; }

                        int st = (int)inst.State;
                        if (st != 1 && st != 2) { skip++; continue; }

                        H3.Workflow.Messages.FinishInstanceMessage msg =
                            new H3.Workflow.Messages.FinishInstanceMessage(iid, (int)inst.FinalTokenId);
                        engine.WorkflowInstanceManager.SendMessage(msg);
                        ok++;
                    }
                    catch (Exception exx)
                    {
                        err++;
                        if (errors.Count < 5) errors.Add(iid + ":" + exx.Message);
                    }
                }

                response.ReturnData.Add("result", "success");
                response.ReturnData.Add("finished", ok.ToString());
                response.ReturnData.Add("skipped", skip.ToString());
                response.ReturnData.Add("notfound", miss.ToString());
                response.ReturnData.Add("error", err.ToString());
                if (errors.Count > 0) response.ReturnData.Add("errorDetail", string.Join("; ", errors));
            }
            else
            {
                response.ReturnData.Add("result", "error");
                response.ReturnData.Add("message", "未知的actionName: " + actionName);
            }
        }
        catch (Exception ex)
        {
            response.ReturnData.Add("result", "error");
            response.ReturnData.Add("message", ex.Message);
        }
    }
}
```

### 3.2 通过 OpenAPI 调用

请求体在标准格式上多传 `Controller` 和 `AppCode`（**接口所在应用**的应用编码，应用列表 → 应用名旁设置 → 重命名弹窗可查）：

```python
from h3yun import H3YunConfig, H3YunClient

client = H3YunClient(H3YunConfig.from_env())

# 只查状态（只读，可用于摸底和复查）
r = client.invoke("QueryInstanceStates", {
    "Controller": "WfFixController",
    "AppCode": "D287764D287765",
    "InstanceIds": "id1,id2,id3",       # 逗号分隔，最多建议500个
})
# r["ReturnData"]["stateTally"]  -> "2:3,4:1" 表示3个进行中、1个已完成
# r["ReturnData"]["runningIds"]  -> 进行中的实例Id列表

# 单条结束
client.invoke("FinishInstance", {
    "Controller": "WfFixController", "AppCode": "D287764D287765",
    "InstanceId": "82810fb7-c3fa-43ba-8d5e-ea39ba8b5002",
})

# 批量结束（只动进行中的，其余自动skip）——注意 50 个/批，见踩坑记录
client.invoke("FinishInstanceBatch", {
    "Controller": "WfFixController", "AppCode": "D287764D287765",
    "InstanceIds": "id1,id2,...",       # 50个以内
})
```

## 4. 批量操作标准流程（生产环境）

按以下顺序执行，每步验证后再进下一步：

```
1. 部署验证     用假实例Id调 QueryInstanceStates，预期返回 stateTally:"-1:1"
2. 全表拉清单   LoadBizObjects 分页（500/批）拉出全部 WorkflowInstanceId
3. 只读摸底     分批 QueryInstanceStates，得到真正进行中的实例清单（≈45%是卡住的）
4. 小批量测试   结束 2~10 个，界面上人工确认"已完成"
5. 全量执行     50个/批循环 FinishInstanceBatch，断点续跑 + 失败自动拆半重试
6. 复查归零     再跑一遍 QueryInstanceStates 全量，确认剩余进行中 = 0
```

现成脚本：`scripts/finish_all_stuck.py`

```bash
python scripts/finish_all_stuck.py --verify    # 只读复查剩余进行中数量
python scripts/finish_all_stuck.py             # 全量执行（断点续跑，清单缓存在 running_ids.json）
```

执行日志按批写入 `scripts/finish_log.jsonl`（finished/skipped/error 明细），可留档审计。

## 5. 踩坑记录

| 坑 | 现象 | 解决 |
|---|---|---|
| **批量大触发平台事务错误** | 500/批批量结束时（批内混有大量已完成实例）报 `System.ObjectDisposedException: MySqlTransaction`，整批回滚 | **50个/批实测稳定**（319批零失败）；出错时对半拆分重试 |
| 表单编码复制不全 | "根据 SchemaCode 获取 BizObjectSchema 失败" | 氚云表单编码是39位，从界面复制时容易丢尾字符，先核对长度 |
| 改 Status 字段走弯路 | UpdateBizObject 改 Status 返回成功且生效，但界面审批状态不变 | 界面状态=流程实例状态，必须走流程引擎（本文方法） |
| 数据 Status 与实例状态脱钩 | 大量老记录数据 Status=1 但实例早已完成；也有 Status=2 但实例还在走 | 判断是否卡住只能靠 QueryInstanceStates 实查，不能拿数据 Status 当依据 |
| LoadBizObjects 返回顺序不按时间 | 抽样前N条不代表最新数据 | 摸底必须全量，不能抽样 |
| `.env` 不会自动加载 | from_env 报"engine_code 不能为空" | 脚本手动解析 .env 后写入 os.environ（见 scripts/ 内实现） |
| 修改数据的副作用 | 接口结束流程 / UpdateBizObject 后 ModifiedBy 变 "System"、ModifiedTime 刷新 | 审计口径上"最后修改人=System"即程序操作，属正常现象 |
